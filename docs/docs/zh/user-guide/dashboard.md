# 仪表盘

仪表盘用于观察当前应用的运行状态、请求趋势和异常情况。它面向日常使用者，不要求理解后端接口细节。

![仪表盘](../../assets/user-guide/dashboard.png)

上图来自 1920×1080 控制台窗口。仪表盘的主要信息集中在请求统计、未知请求监控、核心指标、请求趋势和函数排行。

## 进入仪表盘

登录控制台后，左侧菜单中的“仪表盘”会展示当前选中应用的数据。页面顶部的应用选择会影响所有统计结果；切换应用后，仪表盘会重新加载对应应用的指标。

如果没有看到数据，请先确认：

- 已经选择了目标应用。
- 该应用至少被调用过一次。
- 应用运行时容器已经启动，容器名通常为 `hyac-app-runtime-<app_id小写>`。

## 核心状态区

页面顶部优先展示函数运行状态和未知请求情况。

- 函数状态用于判断当前应用中函数的整体健康度，例如是否有可用函数、是否存在错误调用。
- 未知请求用于发现访问了不存在函数或错误路径的请求，这通常和调用地址、函数 ID、路由路径有关。

当未知请求持续增加时，优先检查外部调用地址是否符合：

```text
https://<app_id>.<DOMAIN_NAME>/<function_id>
```

其中 `app_id` 来自应用管理页面，`DOMAIN_NAME` 来自部署时的环境变量。

## 统计卡片

统计卡片用于快速了解当前应用的总体负载，包括调用数量、成功/失败情况和近期变化。它适合用于判断“应用是否被正常使用”，不适合作为精确审计报表。

如果统计值和预期不一致，建议同时查看：

- 函数管理页的测试结果。
- 日志页或函数详情中的运行日志。
- 运行时容器日志。

开发环境中可使用：

```bash
docker logs -f hyac-app-runtime-<app_id小写>
```

## 趋势图和排行

趋势图展示应用在一段时间内的请求变化。排行列表用于定位调用最频繁或问题最集中的函数。

常见用法：

- 发布新函数后观察请求量是否开始增长。
- 函数报错后查看失败是否集中在某个函数。
- 调整调用方后确认未知请求是否下降。

## 常见问题

### 页面没有数据

先确认当前应用是否已被调用。如果函数从未执行，统计页面可能只显示空状态。

### 请求到了应用域名但函数未执行

检查访问路径是否包含函数 ID。应用子域名只负责定位应用，具体函数仍由路径中的函数 ID 决定。

### 首次请求较慢

应用运行时容器按需启动。首次访问某个应用时，Server 会创建 `hyac-app-runtime-<app_id小写>` 容器，等待健康检查通过后再转发请求。后续请求会直接进入已运行的容器。
